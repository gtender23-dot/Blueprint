# Blueprint bug hunt — 2026-08-07

Read-only audit. **Nothing was changed.** Scope: the subsystem-7 (QB play) pass as the
primary focus, plus a repo-wide sweep of `js/`, `tools/`, the build chain, and `style.css`.

Severity legend: **critical** (breaks build / corrupts saves / blows a stat band) ·
**likely-bug** (wrong behavior, real impact) · **smell** (works today, fragile or
misleading) · **nit** (cosmetic / magic number).

---

## Headline

**No critical issues.** No save-corruption, no build-break, no bug that on its own pushes a
`stat_realism` band out of range. The subsystem-7 code (Fixes A/C/D/E) is, on close reading,
**correct and faithful to the assessment's intent** — the TTT clock is genuinely
sack-neutral, the scramble-to-throw is consistent with the main INT path, read-conflict and
checkdown scale the right direction. The freshest risk was clean.

The worst things found are elsewhere and mostly pre-existing:

1. **Interceptions on two throw paths are counted under the wrong keys** (`sim.js` 1313,
   1433) — they never reach the QB's `passInt`, the DB's `ints`, or the `stat_realism` INT%
   aggregate. This is the single most consequential finding because **INT% is a veto metric**,
   it currently reads *below* its band (1.76 vs 1.8 floor), and this bug biases it *downward* —
   so part of the "deliberate below-band calibration" that **killed Fix B** may actually be a
   counting error. (likely-bug)
2. **`yacgeo.js` inverted `behind` flag** (~275) suppresses the explosive-YAC tail the fix was
   built to create. (likely-bug)
3. **`formations.js` fields a "5-2" front as a 4-3** (~44) — the called short-yardage run
   front is not the front on the field. (likely-bug)
4. **`sw.js` ships a hardcoded cache hash** instead of the `__BUILD_HASH__` placeholder — a
   baseline-idiom violation that makes source masquerade as built output. (likely-bug)
5. **Three probes can't fail for their own regression** (`motion_struct_probe`,
   `situational_probe` Fix E, `kicker_check`) — they green-light dead code. (likely-bug)

## Cross-cutting — interception accounting (touches the INT% veto)

**`js/engine/sim.js` 1313 & 1433 — INT written under keys the tally doesn't read — likely-bug.**
Two throw outcomes record an interception as:
```
result.turnoverType = "INT";   result.intById = <id>;
```
- 1313 — batted-ball tipped INT (`BAT_TIP_INT`)
- 1433 — deep fade / back-shoulder shot INT (fires ~6% of contested deep fades)

But the box-score tally reads different keys:
- **QB `passInt`** (5064): counted only when `turnoverType === "interception"` → these two miss.
- **DB `ints`** (5081): counted only from `intPickerId` → these two set `intById`, so miss.

Every *other* INT path uses `"interception"` + `intPickerId` (main catch resolution 1954, and
the new scramble-throw 1491), which is the convention the tally and UI actually consume
(`sim.js` 4019/5064, `app.js` 1188/2294). So 1313/1433 are the odd two out.

**Why it matters:** `stat_realism_harness` builds INT% from `ps.passInt` (line 79) and team
turnovers from `ps.ints` (line 69) — **both** of which exclude batted-tip and deep-fade picks.
So the harness under-reports INT%. INT% is a veto metric sitting *below* its floor (1.76 vs
1.8), and the QB-play writeup treats that as "a deliberate coverage-pass calibration choice"
that had no headroom for Fix B — **but some of that deficit is this miscount, not calibration.**
Possession still flips correctly (the drive logic keys on `turnover`, not the string), so this
is a stat-attribution + display bug, not a gameplay one.

Related fallout from the same split:
- **`sim.js` 4019** labels these picks `"FUMBLE"` in the play log (`=== "interception" ? INT : FUMBLE`).
- **`highlights.js` 66** checks `turnoverType === "INT"` — the **inverse** of everything else —
  so the highlight reel catches *only* batted-tip/deep-fade picks and misses normal coverage
  INTs and scramble-throw INTs. (smell → likely-bug for the reel)

**Fix direction:** normalize 1313/1433 to `turnoverType = "interception"` and
`intPickerId`; fix `highlights.js` 66 to match; then re-baseline INT% — it may already be closer
to band than the writeup assumes, which could re-open the Fix-B question.

## `js/` sim/geometry

### `js/engine/yacgeo.js`
- **~275 — inverted `behind` flag — likely-bug.** Runner always moves +y; a pursuer *trailing*
  the runner has smaller y, so `gy = car.y - d.y > 0`, making `behind = gy < -0.5` **false** for
  the actual trailing defender. Result: trailing pursuit gets the `Math.max(2, …)` closing floor
  the fix meant to *remove*, and downfield defenders get the negative-closing allowance instead —
  suppressing the documented breakaway/explosive-YAC tail. Fix: `gy > 0.5` (or swap the two
  `Math.max` branches). *Correcting this raises YAC/pass-yds — re-run the YAC + stat_realism
  probes after.*
- **~326 — phantom tackler on a house call — smell.** When the runner reaches `MAX_Y` (nobody
  tackled), `tacklerId` falls back to `coveringDef.id`, crediting the beaten corner with a tackle
  on a broken play. `run2geo.js` returns `null` in the same case — the two disagree. Fix: drop
  the fallback.

## `js/` game flow / state

### `js/engine/formations.js`
- **~44–59 — "5-2" front fielded as a 4-3 — likely-bug.** `selectDefFront` returns `"5-2"` on
  3rd/4th-and-1 vs non-spread, and `sim.js` (~3517) routes it through `resolveDefPersonnel`, but
  `FRONT_COUNTS` and `RUSH_SLOTS` have no `"5-2"` entry → falls back to 4-3 counts. So the
  matchup matrix / field layout score it as a true 5 -man-front run wall while the defense
  actually fields 4 DL + an extra OLB + 1 LB. Weakens a high-leverage short-yardage down and
  means the called front ≠ the front on the field. Fix: add `"5-2"` to `FRONT_COUNTS`
  (`{DE:2, DT:3, OLB:0, LB:2, CB:2, S:2}`) and `RUSH_SLOTS` (`["DE","DT"]`).

  save path refuses to serialize a live pause (the CLAUDE.md rule); export doesn't. Recoverable
  (`rehydrate` drops the pending pause on import, `resolveStaleGames` replays), so not corruption
  — but it's a save path bypassing the documented gate. Fix: block export when paused live.

### `js/engine/season.js`

  recovery path, low severity.
- **~191 — magic `19` — nit.** `Math.max(1, 19 - day + 1)` hardcodes the recruiting-close day

### `js/engine/ai.js`

- **`motion_struct_probe.mjs` ~48–66 — likely-bug.** Header declares an "IT FIRES" firing-counter
