This is a plain-language map of what your simulation actually computes, pulled directly from the current js/ source and with the real numbers substituted in. It's a private tuning reference, so it prints coefficients freely — the "never show a coefficient" rule is for the in-game manual, not for you. Every formula cites its file:line. Where a code comment, a probe, or your notes disagree with the arithmetic that's actually shipping, the math wins and the gap is flagged. The big payoff of doing it this way: it caught four "known bugs" from your notes that are already fixed — and two features that are quietly inert. See the appendix.

§How to read this

A few conventions used everywhere below:

  • clamp(x, lo, hi) keeps a value between two bounds. logistic(x) = 1/(1+e−x) is the S-curve that turns "how much better is A than B" into a probability.
  • randNorm(μ, σ) is a bell-curve draw (mean μ, spread σ). random() is a flat 0–1 roll.
  • Attributes are the 0–99 ratings: SPD speed, AGI agility, PWR power, STR strength, JMP jump, HND hands, SEC security, TEC technique, AWR awareness, plus meta CON conditioning and WE work ethic.

§Shared scales & the ±0.01 rule

Two conversions recur across the whole on-field engine. Every "dot" that moves on the field uses the same attribute→physics scale:

top speed   = 6.4 + SPD·0.028   yd/s     (SPD 50 → 7.8,  SPD 90 → 8.9)
accel       = 7.0 + AGI·0.05    yd/s²
defender scale is COMPRESSED:  attr' = 50 + (attr−50)·0.35   (chase geometry only)
simulation tick = 0.1 s  (10 Hz)

And the number the whole passing game pivots on is separation (0–1, where 0.42 is a coin-flip window). It feeds the completion sigmoid at slope 5.0, which is why the codebase is so disciplined about it:

Every 0.01 of separation ≈ 1.2% of completion. That's why a bug that quietly shifted the press bucket by 0.04 was worth four to five points of league-wide completion. When you tune anything upstream of a catch, watch the separation buckets, not the yardage.

Vision (scouted) rating — the whole scouting game

visionRating = round( posAdjust( mean(all 11 attributes) + 7.5 , position ) )

Vision is the raw unweighted average (what a naive eye sees); OVR is the weighted one (what actually plays). The +7.5 (VIS_CENTRE) cancels the structural bias by which a weighted average beats a raw one, so the two live on one scale. player.js:604

truth − vision ≥ 12 is a "gem" (unspectacular numbers that happen to be the right numbers); vision ≫ truth is a "workout warrior." That gap is what your talent-evaluator skill exists to read.

2Archetypes — the relative-lean method

A player is classified by his own attribute contrasts, never an absolute bar, so it's division-proof. The building block: player.js:272–276

axisLean(groupA, groupB) = avg(attrs in A) − avg(attrs in B)

Each position runs a small decision tree of lean thresholds (ARCHETYPE_DERIVE, player.js:78–223). Examples:

QB:  legLean = avg(SPD,AGI) − avg(STR,TEC)
     legLean > −3 → Scrambler ; > −9 → Dual ;
     else giLean(AWR−STR) > 5 → Game-Manager ; armLean(STR−TEC) > 5 → Gunslinger ; else Pocket
CB:  zoneLean = avg(AWR,TEC) − SPD > −23 → Zone ; ballLean(HND−STR) > 20 → Ball ;
     physLean(STR−AGI) > 2 → Press ; else Slot
RB:  blockLean = avg(PWR,STR) − avg(SPD,AGI) > 26 & SPD<62 → FB tier ; else
     Workhorse / Speed / Elusive / Power / Scat by the strongest lean
Instead of "is he faster than the league," it asks "which of his own skills outweighs the rest" — so a 55-OVR D3 corner and a 95-OVR D1 corner with the same shape get the same label. (Many thresholds are deeply negative because a position's core stats structurally dominate; that's calibration, not a bug.)

3Recruit generation

The class is sized to league need: poolSize = round(demand × 1.3) where demand = graduating seniors + walk-on slots + roster vacancies. Each recruit's tier (1=D3, 2=D2, 3=D1) is drawn in proportion to the league's division counts. world.js:2684

Attributes start from a tier base and get shaped in passes: player.js:411–638

base = DIV_BASE_BY_TIER[tier] + (prestige−3)·2      DIV_BASE = {D3:19, D2:33, D1:49}
star roll:  rand() < clamp(STAR_RATE[tier] + prestigeBonus·0.010, 0.02, 0.45)
            STAR_RATE = {D3:0.10, D2:0.18, D1:0.30}
core attr:  clamp(round(randNorm(base + threshold·0.6, 8)), 1, CORE_CAP)   CAP = {D3:78,D2:88,D1:95}
build type: 6% "workout warrior" (measured +12..24, coached −6..16) ; 6% inverse ; 88% normal
STR/PWR couple: STR = max(STR, base·0.35 + avg(SPD,AGI)·0.35 + N(0,6)) ;  PWR = 0.45·PWR + 0.55·STR + N(0,5)
then: archetype skew → QB mobility molding → division physical caps → positional floors (tier-scaled)
Most kids are "normal," but about one in eight is a boom/bust athlete-vs-technician — and that split is exactly what makes scouting matter. Strength and power are correlated on purpose, so you rarely get a 99-STR/40-PWR freak.
flagThe "physical" caps aren't physical-only. Comments call the capped set the five athletic attributes, but the real constant CAPPED_ATTRS is nine (everything except CON/WE) — so division ceilings and spawn caps also bind HND/SEC/TEC/AWR, contrary to the "athletic body" framing. constants.js:20

4Potential & the development ceiling

A potential "band" is rolled (prestige tilts it), then each attribute gets a personal ceiling: player.js:337–369

band spreads (mean growth above current):  average 15 · good 23 · great 33 · sky 47
cap[a] = clamp( attr[a] + round(randNorm(spread, 6)), attr[a], ceil )
work-ethic overage:  weBonus = clamp(round((WE−55)·0.22), 0, 7)   → softCap = physCap + weBonus
archetype tilt:  signature attributes get up to +6 headroom above the division cap
Everyone in a division shares a talent wall, but the attributes an archetype leans on can climb ~6 points higher, and a genuine grinder (high WE) can nudge the whole wall up 7 more. Note spread is the mean growth, not a spread — a "sky" attribute grows ~47 points on average.

5Athletics (RAS) & size

Combine numbers generate backward from measured attributes through real NFL per-position percentile tables, then Athletics re-reads them as percentiles. player.js:747–846

attr → NFL percentile:  pct = −0.60 + (attr/100)^1.05 × 1.70     (attr 50≈p22, 90≈p88, 99≈p108)
forty  = drillAt(Forty,    1 − spdPct)      // timed drills invert
bench  = drillAt(BenchReps, str·0.7 + pwr·0.3)
broad  = drillAt(BroadJump, (jmp+pwr)/2)
RAS    = mean(available percentiles) × 10    (rounded to 0.1)

Height/weight share one roll so tall/heavy and short/lean correlate: player.js:381–409

hFrac  = clamp(randNorm(0.5, 0.22), 0, 1)          // shared by height & weight
weight = clamp(round( w_base(hFrac) + (STR−50)·0.35 − ((SPD−50)+(AGI−50))·0.18 ), wMin−12, wMax+18)
Raw ratings become believable 40 times, bench reps and verticals drawn from actual NFL position data; Athletics is just the average percentile those land at — an honest athleticism grade, not a separate invented stat.
noteRAS effectively spans ~1.0–9.0, not the "0–10" the comment claims, because in-range percentiles are floored/capped at 0.10/0.90.

6Separation — the route duel

A 10 Hz two-dot physics duel: the receiver runs a scripted route, the defender plays his technique, and the distance between them at the throw is rank-mapped to a 0–1 separation. Every catch, read, and INT reads this one number. sepgeo.js:104

route scripts [stem yards, throw time, break time]:
   short  [ 5, 1.6, 1.05]     medium [12, 2.4, 1.85]     deep [26, 3.0, 2.45]
cut quality  = 1.0 + (TEC−50)·0.0045 + (AGI−50)·0.0032        // speed kept through a plant
the sell     = clamp((rec.TEC − def.TEC)·0.0040, −0.20, 0.20) // route craft freezes the mirror
man reaction = 0.12 + max(0, 78−AWR)·0.0016  (+ the sell)
zone trigger = 0.07 + max(0, 88−AWR)·0.0015
distance → sep:  sep = clamp( qinterp(QMAP[depth/technique], rawDistance) + 0.015, 0, 1 )
The physics decide who's open and why (the rank); a per-bucket quantile map (QMAP) sets the scale the downstream catch math was built on. If no defender is in the play, separation is a flat 0.84 (zone) or 1.0.

7The press jam

Two contested blends, cashed out as time. This is the July-2026 corrected model. sepgeo.js:131

jam     = def.STR·0.40 + def.TEC·0.35 + def.AGI·0.25 + 1
release = rec.AGI·0.40 + rec.TEC·0.35 + rec.STR·0.25
jamGap  = (jam − release) × (pressHot ? 1.08 : 1)

defender WINS (jamGap ≥ 0):
   recDelay  = min(0.42, 0.14 + jamGap·0.0075)   // receiver held
   def.lag   = recDelay                          // defender held the SAME beat (cancels!)
   rec.acc  *= max(0.55, 1 − jamGap·0.0085)      // THE PAYOFF: laboured release
receiver WINS (jamGap < 0):
   def.lag   = min(0.38, 0.10 − jamGap·0.0065)   // beaten clean
fixedThis is the load-bearing correction. Delaying both men by the same beat cancels (shifting both along one path leaves the distance unchanged). The real effect of a won jam is the degraded receiver acceleration — he rebuilds speed, hits top speed later, breaks from a shallower point. The old bug delayed only the receiver while the corner free-ran, which inverted press (winning the jam made a corner worse). PRESS_RECENTER is now retired — the QMAP press buckets were refit against live post-fix distances.

8Completion & interception

Completion is a sigmoid in separation, lifted by QB accuracy/arm and (on jump balls) size, cut by pressure and coverage. sim.js:726–777

qbExec    = min( (QB.TEC·0.5 + QB.AWR·0.5 − 91)·0.0184 + 0.32 , 0.38 )
armFactor = (armAttr − 50)·0.006      armAttr = PWR(short) | STR(deep) | avg(medium)
sizeMismatch (medium/deep, tight windows) = (heightGap·0.040 + jumpGap·0.010)·clamp(1−sep,0,1)

catchProb = clamp( logistic( (sep − 0.42)·5.0 + qbExec + armFactor + sizeMismatch
                             − (hurried ?0.22:0) − (bracketed ?0.12:0) − (forced ?0.45:0) )
                   × (1 + dnaAirBoost), 0.04, 0.97 )

At the 0.42 pivot an average QB lands ~62%; elite accuracy caps near 70–72%. On an incomplete with a covering defender, the pick branch fires: sim.js:791–859

defRead   = DB.AWR·0.40 + SPD·0.22 + JMP·0.13 + HND·0.13 + TEC·0.12 + 2.9
intProb   = clamp( 0.066·(1−sep)·(defRead/55)·depthMult × [qb·forced·passKey·style·aggr·dna·arm mults],
                   0.003, 0.19 )
depthMult = 1.5 deep / 1.0 else ;  style = zone 1.18 / man 0.85 ;  forced 1.6 ;  deep help safety gets a 2nd crack
Both completion and picks scale with how covered the man is (1−sep): tighter windows drop the catch and raise the pick — most on deep balls, in zone, and when you force it to a covered star.
flagThe header comment references CATCH_SEP_SCALE / CATCH_TECH_SCALE constants — neither exists. The slope is a hard-coded 5.0 and accuracy is the qbExec blend. Dead comment refs at sim.js:728,753.

9Yards after catch

After the catch, the dots are released for a pursuit sim (caps: 5 s, 72 yd). The separation at the catch becomes the covering defender's literal head-start distance. yacgeo.js:61

carrier: top = spd(SPD), acc = acc(AGI), first step at 45% speed (securing the ball)
wiggle  = AGI·0.7 + TEC·0.3
covering def starts at y = −(0.4 + sep·3.2)          // sep → head start
vision  = clamp(3.2 + (AWR−41)·0.025, 2.4, 4.6)      // how far ahead he reads threats
cut     = clamp(0.35 + (AWR−41)·0.0025 + (AGI−41)·0.0015, 0.20, 0.55)   // each cut bleeds speed
finish (tackle):  pMake = 0.74 + (tkl − wiggle)·0.005 − (AWR−41)·0.0016   // miss = broken tackle
variance: 38% "stretched" (soft zone) vs 42% "swarm" (defender sitting on the spot → the fat-zero column)
cavalry: 2 more flankers arrive at t ≥ 1.4 s (why escapes become first downs, not TDs)
Openness at the catch is the pursuit's head start; then speed and elusiveness race the closing angles. Every cut bleeds speed while the angles keep shrinking, so most YAC is short — big gains come from broken tackles and stretched zones, and deep safeties cap the breakaways.

11Block reps — who wins the trench

Every rep is a weighted attribute contest run through one sigmoid. Losers "penetrate." sim.js:296–414

repWin(off, def, ctx) = logistic( (off − def)/24 + ctx )      ctx = (offUnit − defUnit)/145
PASS block:  blkVal = STR·0.30 + TEC·0.28 + PWR·0.22 + AWR·0.20 + center + mirror(AGI)
RUN block:   blkVal = PWR·0.30 + AWR·0.28 + STR·0.22 + TEC·0.20 + 10.7
             shedVal = STR·0.34 + AWR·0.28 + PWR·0.22 + TEC·0.16 + 4.6
size term:   (blockerWt − rusherWt)·0.10 × (edge/speed rush ? 0.25 : 1)
reach/pull mobility bonus: ((AGI−20)·0.6 + (SPD−20)·0.4)·0.7   (POA + puller only)
Pass pro is strength + technique + a mobility term for mirroring speed; run blocking is drive (PWR/STR) + read (AWR). A weight mismatch tips the rep, and equal weights are neutral.

12The pocket race — sacks & hurries

The QB holds an internal clock; each rusher who won his rep sprints at the launch point. Fastest arrival < clock = sack; just late = hurry. Zero penetrators = always clean. rushgeo.js:91–138

clock    = 2.20 × (1 + (protectMult−1)·0.17) × (1 + paBite·0.26)
collapse = 0.12 × (numPenetrators − 1)          // each extra rusher caves the pocket for everyone
per rusher:
   path     = 5.35 (edge) | 4.45 (interior)
   closeSpd = 7.35 + ((SPD·0.6 + AGI·0.4) − 55)·0.010
   free blitzer:  shed = 3.38 − 3.38·designPull + N(0,0.72)
   beat block:    shed = 2.90 − (rPow − bPow)·0.0022 − (power ?0.22:0) + N(0,0.72)
   arrival  = clamp(shed,0.55,5.00) + path/max(3,closeSpd) − collapse
SACK if min(arrival) < clock ;  else HURRY if < clock × 1.50 × (1 + passKey·0.011) × (1 − paBite·0.26)
Attribute influence here is deliberately flat (the block-win contest upstream already priced the players). The sack rate is carried by the count of free rushers via collapse, not any one rusher's speed — which is why sending more bodies works.

13Scramble & sack conversions

A pressured or sacked mobile QB can bail and run, measured relative to his own passing baseline (division-proof). sim.js:2120–2134

mob = (SPD+AGI)/2 ;  pocket = (STR+TEC+AWR)/3 ;  lean = mob − pocket ;  absMob = (mob−50)/40
scrambleChance = clamp( (absMob·0.5 + lean/40·0.6)·0.40 + 0.04, 0.02, 0.45 )
on a sack:  × 0.55 if spied, × (zone 0.85 | man 1.10)
on pressure (not sacked):  × 0.8   ← the bulk of scramble volume
A dual-threat scrambles even without elite raw speed, because it's judged against how good a passer he is; a spy and man coverage shrink both the odds and the running lane.

15Mesh, contact & breakaways

A won line moves the mesh point forward and lets the back hit the hole rolling. run2geo.js:63,138–144

laneShift = (lane − 0.60) × (lane < 0.60 ? 0.26 : 0.19)    // downside steeper: penetration hurts more
carrier start y = −3.92 − 0.16 + laneShift                 // mesh depth behind LOS
entry = 0.712 + (lane − 0.60)·0.028 + (rand−0.5)·0.18 + clamp(vision·0.05, −0.12, 0.12)
carrier.vy = top × entry                                    // downfield launch speed
LB fill:  blockedP = clamp(0.67 + (lane−0.60)·0.12 + vision·0.10, 0.15, 0.92)  // higher lane → fewer free hats
yards after contact (drag): car.y += min(2.6, max(0, vy−1.6)·0.155·drag)·clamp(y/2.5,0.35,1)
breakaway: clear all but ≤1 man past ~9 yd → +14..38 yд ; clear everyone → +26..68 (house call)
A penetrator only gets a capped diving ankle-grab, which is what keeps a won line "worth tenths, not whole yards." Breakaways are pure angle arithmetic — clean lanes feed them because the higher launch and fewer free hats get the back to the second level at pace — not an absolute-speed dice roll.

16Broken tackles

The back rolls both an escape and a truck and takes the better one; this redistributes tackle credit and lets the geometry roll on — it doesn't add yards directly. sim.js:949–965

evadeGap = (AGI·0.55+SPD·0.27+TEC·0.18)car − (AGI·0.34+SPD·0.26+AWR·0.22+TEC·0.18)def
truckGap = (PWR·0.55+STR·0.27+TEC·0.18)car − (STR·0.34+PWR·0.28+TEC·0.20+AWR·0.18)def
chance   = clamp( 0.03 + (max(evadeGap,truckGap) − 8)·0.016
                  + max(0, weight−210)·0.00075 + (AWR−41)·0.0018, 0, 0.40 )
strip tackler: +break chance ; wrap tackler: −break chance ; cap 2 broken tackles per carry
A 90-AWR back gets about +0.09 break chance; each pound over 210 adds ~0.00075. Capped at 40% per attempt and two per carry so it stays realistic.

19Recruiting economy

The master "fit" formula turns dollars into effective spend — the same money lands differently on different kids. recruiting.js:198

effectiveSpend = dollars × distanceMod × prestigeMod × recruiterMult × repMult
                 × rootsMult × wantMod × classNeedMod × ptMod

distanceMod   = {local 1.25, near 1.0, mid 0.7, far 0.45} × 1/(1+max(0,d−700)/1800)
prestigeMod   = clamp(0.5 + prestige·0.15, 0.5, 2.0)
